# 🛡️ Cybersecurity Portfolio

Welcome to my hands-on cybersecurity portfolio.

I am currently transitioning into cybersecurity while studying **CHCSS – Certified Hands-on Cyber Security Specialist + Linux** at Kernelios Institute.

This portfolio documents my practical learning journey through structured projects, labs, technical experimentation, and security analysis.

My goal is not only to learn cybersecurity concepts, but to apply them in practice — **building, testing, analyzing, documenting, and improving** along the way.

---

## 📖 One Organization, One Story

All six projects take place in the same fictional organization: **ShayVis Ltd**, a ~60-employee company with an office network, a Windows domain, and a Linux server hosting a customer-facing web portal.

Throughout my training, I take the role of its first security practitioner:

**🏗️ Build it → 🎯 Test it → 🛡️ Monitor it → 🚨 Respond → ⚙️ Automate → 📊 Report**

Each project builds on the environment and findings of the previous one, so design decisions, findings, detections, and lessons learned can be traced across the entire portfolio.

> ShayVis Ltd is fictional. All work is performed in an isolated lab environment that I own.

## 🔬 Project Methodology

My projects follow a practical and evidence-based workflow:

**📚 Learn → 🛠️ Build → 🧪 Test → 🔎 Analyze → 📝 Document → 🔁 Improve**

Each project is intended to include:

- 🎯 Clear objectives and scenario
- 🏗️ Architecture and environment documentation
- ⚙️ Configuration and implementation
- 🧪 Testing and validation
- 📸 Technical evidence and screenshots
- 🔎 Findings and analysis
- 🛠️ Remediation and improvements
- 💡 Lessons learned
- 📋 Known limitations
- 🧭 What I added beyond the course material

## 🤖 AI-Assisted Learning

AI tools may be used throughout this portfolio to support learning, troubleshooting, research, documentation, and idea development.

However, the goal is to maintain a **human-validated workflow**:

- Understand the concepts before implementation
- Review and test suggested commands or configurations
- Validate results in the lab environment
- Document what was performed and why
- Be able to explain the implementation and findings independently

AI is used as a **learning and productivity tool**, not as a substitute for technical understanding.
